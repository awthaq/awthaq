"@awthaq/organization": minor
"@awthaq/saml": minor

SAML and OIDC connections now share one lifecycle, `OrganizationConnectionLifecycle` in `@awthaq/organization` (an exposed organization service, `awthaq/plugin/organization/ConnectionLifecycle`, parameterised by a protocol descriptor). A suspended organization can no longer gain, change or refresh a SAML connection (it could before): the attempt is refused exactly like one for an organization that does not exist, and removing the connection stays allowed. A claim on an email domain and its connection write are one unit: on Postgres every claim and release of an organization takes a transaction-scoped advisory lock (`organization_domain_claim:org:<organizationId>`) and inserts owner rows in sorted domain order, removal releases the claims before the connection row, and create re-checks the organization under the lock, so concurrent connection writes no longer deadlock and no domain stays claimed by a deleted connection or organization. A write that finds its connection already removed releases that connection's claims instead of restoring its previous ones. Over SQL the unit is one transaction, so a failed write leaves the claims as they were; the in-memory twin has no lock and no rollback (a test double), so it compensates a failed write but does not serialise two fibers racing on one connection. A protocol's write runs under that lock and must perform no external IO, so the OIDC store now seals a client secret in its `prepare`, before the lock and the transaction: `ConnectionRecords.sealSecret` and `PreparedSecret` are new at `@awthaq/organization/records`, and `create` and `update` accept the prepared secret as well as the plaintext. The refusal for a taken domain still names the first foreign domain in the order given.

Migration: `DomainClaims` is no longer exported from the root of `@awthaq/organization`; import it from `@awthaq/organization/records` to compose a records bundle or in tests. `DomainClaims.withClaim` and `DomainClaims.withRelease` are removed: protocol code calls `OrganizationConnectionLifecycle` with a `ConnectionProtocol` descriptor (`create`, `update`, `remove`); the descriptor's `isGone` says which write failure means the connection no longer exists (`ConnectionRecordNotFound`, `SamlConnections/NotFound`), and a create's `connectionId` must be freshly generated by the protocol. `Organization.Organization` now exposes the service `awthaq/plugin/organization/ConnectionLifecycle`, so an application that names the organization's exposed services by type (as the example servers' `OrganizationServices` does) must add `OrganizationConnectionLifecycle.OrganizationConnectionLifecycle`, and a composition that builds `OrganizationConnections.layerStore` without `Organization.Organization` provides `OrganizationConnectionLifecycle.OrganizationConnectionLifecycle.layer` (over `DomainClaims`, `OrganizationDirectory` and `SqlTransaction`). `connectionsOnOrganizationDelete` no longer releases domain claims: the organization's own deletion contribution does. Callers that created, updated or refreshed a SAML connection for a suspended organization now receive `InvalidSamlConnection` (`InvalidSamlConnectionRequest` on the endpoint) with the reason "the organization does not exist".
