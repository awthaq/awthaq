# MTS-011 — Generated quality dashboard is committed while its inputs are gitignored

`LOW` · `dx` · `—` · reported by **Monorepo Tooling Specialist** (`monorepo-tooling-specialist`)

Status: **ready-for-human**

## Summary

type-quality-dashboard.html is tracked at the repo root (verified via git ls-files) and is regenerated by scripts/generate-quality-dashboard.mjs from .quality-metrics/*.json — but .quality-metrics/ line 6 of .gitignore excludes exactly those inputs, and zero of them are tracked. A fresh clone therefore contains a committed dashboard artifact that cannot be regenerated or updated from repository state alone; whoever has the metrics locally can silently overwrite the committed HTML with unreproducible content. Pick one side of the boundary: generated output ignored, or inputs committed.

## Evidence

Source: `.gitignore:6`

```
coverage/
*.tsbuildinfo
.quality-metrics/
```

## Recommended fix

Track .quality-metrics/*.json (they are the auditable 50-KPI evidence) and gitignore the rendered HTML, or ignore both and publish the dashboard as a CI artifact.
