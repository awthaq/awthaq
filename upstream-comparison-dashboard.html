Headline findings

Divergent by construction, not by patch

Git histories share zero commits — awthaq is a fresh-root rewrite (33 commits, 2026-09-13→14, no remote) of a dormant upstream (75 commits, silent 119 days). Nothing can be cherry-picked; every upstream improvement must be ported by hand.

Session expiry models are philosophically opposed

awthaq: absolute cap (30 d) + sliding idle (7 d), hard-delete revocation, constant-time compare, enumeration-safe 404s. Upstream: sliding-only (an active session never expires), soft revokedAt stamps, and true token rotation on refresh — which awthaq deliberately lacks.

Cookie hardening vs configurability

All awthaq cookies are compile-time-constant __Host- prefixed, Secure+SameSite=Strict, with a dedicated rotating CSRF cookie + header. Upstream allows any RFC-token cookie name, defaults SameSite=Lax, derives Secure from baseUrl (non-Secure on http), and mitigates CSRF by Origin/Referer validation instead.

Password hashing: argon2id vs scrypt

awthaq defaults to OWASP-baseline argon2id (hash-wasm, edge-portable) with 6 env-tunable knobs, needsRehash-on-login, and constant-cost sign-in via a boot-time dummy hash. Upstream hardcodes scrypt N=16384,r=16 (≈4× cheaper than awthaq's fallback) in a custom hash format.

4 of 21 packages are empty placeholders

two-factor, magic-link, api-key, cli export {} — announced on the M7 roadmap. Upstream has a working CLI (effect-auth generate) and a real email-verification flow where awthaq has specs only. Local designs ahead, upstream ships more of the basics.

Upstream wins onboarding; local wins existence

bun add effect-auth + 26-line quickstart + 2 runnable examples + npm badges vs a 125-line clone-and-build quickstart and zero published packages (all 21 private:true).

Type discipline is a mirror image

Upstream src is literally any-free (0 escape hatches) and pins all 20 Effect language-service diagnostics to error. awthaq carries 88 anys + stricter tsconfig flags (noUnusedLocals, noImplicitOverride…), 5 branded ID types, and a negative type-test suite upstream lacks.

Security controls: 8/8 vs 6/8 — different halves

Upstream has session-token rotation, sign-in email-verification gate, and node timingSafeEqual; awthaq has double-submit CSRF, PKCE + encrypted OAuth state, JWT key rotation with live sid revocation, and HIBP breach checks. Each side covers what the other skipped.

Data model: integrity in the DB vs in the domain

Upstream DDL: 3 FK ON DELETE CASCADE + 11 secondary indexes + db-unique email. awthaq DDL: 0 FKs, 2 indexes — cascade and uniqueness live in core services; in exchange, UUIDv7 ids, two-tier session expiry columns, insert-only secret hashes, and actor-tracking columns.

Org/RBAC/passkey/JWT/admin exist only here

37 organization endpoints over 7 tables, statement-based PermissionEngine, WebAuthn ceremonies with AAGUID tracking, EdDSA/ES256 signing + JWKS + key rotation, audited impersonation — 0 upstream matches for all of it.
