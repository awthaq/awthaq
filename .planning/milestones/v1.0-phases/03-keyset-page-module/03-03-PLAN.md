Target API of packages/ports/src/Keyset.ts (03-RESEARCH.md Pattern 1, option C; names fixed here so 03-04..03-07 can rely on them):
- `MIN_LIMIT = 1`, `MAX_LIMIT = 200`, `DEFAULT_LIMIT = 50`; `limit(requested: number | undefined): number` (undefined or non-finite -> DEFAULT_LIMIT, else truncate and clamp to MIN_LIMIT..MAX_LIMIT).
- `interface Page<Item, Cursor> { readonly items: ReadonlyArray<Item>; readonly nextCursor: Option.Option<Cursor> }`
- `interface Request<Cursor> { readonly after: Option.Option<Cursor>; readonly limit?: number | undefined }`
- `interface Fetch<Cursor> { readonly after: Option.Option<Cursor>; readonly take: number }`
- `type Direction = "asc" | "desc"`
- `interface Key<Row, Cursor> { readonly column: string; readonly direction: Direction; readonly rows: Order.Order<Row>; readonly against: (row: Row, cursor: Cursor) => Ordering.Ordering }` where `rows` and `against` already apply the direction (the value type V is hidden in closures, so keys of different value types share one tuple with no `any`).
- `key<Row, Cursor, V>(spec: { column: string; direction: Direction; order: Order.Order<V>; row: (row: Row) => V; cursor: (cursor: Cursor) => V }): Key<Row, Cursor>`
- `interface Declaration<Row, Cursor> { readonly keys: readonly [Key<Row, Cursor>, ...Array<Key<Row, Cursor>>]; readonly cursorOf: (row: Row) => Cursor }`
- `window<Row, Cursor>(declaration, rows: Iterable<Row>, fetch: Fetch<Cursor>): ReadonlyArray<Row>`
- `paginate<Row, Cursor, E, R>(declaration, request: Request<Cursor>, fetch: (fetch: Fetch<Cursor>) => Effect.Effect<ReadonlyArray<Row>, E, R>): Effect.Effect<Page<Row, Cursor>, E, R>`

Effect v4.1.2 pieces (present in node_modules/effect/dist): `Order.String` (code unit), `Order.flip`, `Order.combineAll`, `Order.mapInput`, `DateTime.Order`, `Ordering.Ordering` (-1 | 0 | 1).

The declarations 03-05..03-07 will write (for the spike): users `createdAt` asc with `DateTime.Order` then `id` asc with `Order.String`, cursor `{ createdAt: DateTime.Utc; id: string }`; impersonations `startedAt` desc then `id` desc, cursor `{ startedAt: DateTime.Utc; id: string }`.

Today's memory formulas the parity tests compare against (copy them into the test as local oracles, never import them): users sort by epoch millis of `createdAt` then `a.id < b.id ? -1 : a.id > b.id ? 1 : 0`, keep rows whose (millis, id) is strictly greater than the cursor's (packages/ports/src/UserStore.ts:183-186, 359-381); impersonations newest first by (millis of `startedAt`, id code unit) and keep rows strictly before the cursor (packages/admin/src/ImpersonationRecords.ts:194-219).
