Shape of `packages/sql/src/CoreTables.ts` (RESEARCH "Pattern 1", prototype compiled with the repo tsc, no assertions). Declarations, in prose:
- `type Tenancy = "partitioned" | "directory" | "none"` (`none`: the table has no `"tenantId"` column).
- A private `declared` constant: an `as const` tuple of eight rows in migration-creation order, each `{ name, tenancy, replicated }` plus `reason` on the two `none` rows. Rows: users directory true; accounts directory true; sessions partitioned true; verification_tokens partitioned true; verification_reservations partitioned true; auth_audit_log partitioned true; auth_relay_cursor none false (reason); rate_limit_buckets none false (reason).
- `type CoreTableName` = the union of the eight names (from `declared`).
- `interface CoreTable { readonly name: CoreTableName; readonly owner: "core"; readonly tenancy: Tenancy; readonly replicated: boolean; readonly sealed: ReadonlyArray<SealedColumn.Sweepable>; readonly reason?: string }`.
- Exported views, each an explicitly typed `const`, each a `filter`/`map` of `declared` or `tables`, never sorted: `tables: ReadonlyArray<CoreTable>` (rows plus `owner: "core"` and `sealed` = `CoreSealedColumns.deployed({ encryptPii: true })` filtered on `column.table === name`); `names: ReadonlyArray<CoreTableName>`; `partitionedTables` typed `ReadonlyArray` of the four partitioned name literals; `directoryTables` typed `ReadonlyArray` of "users" | "accounts"; `stamped: ReadonlyArray<CoreTableName>` (tenancy not `none`); `replicated: ReadonlyArray<CoreTableName>`; `isStamped(name: string): boolean`.
- Typing notes from RESEARCH: TypeScript infers the type predicate of `(entry) => entry.tenancy === "partitioned"` over the `as const` tuple, so `.filter(...).map((entry) => entry.name)` keeps the literal union with no assertion; a generic `withTenancy<K>` helper does NOT compile (TS2322), write one explicit `const` per view; `ReadonlyArray<literal union>.includes(someString)` does not compile, hence `isStamped(name: string)` (for example `stamped.some((table) => table === name)`).
- Classification reasons (Q4 plus the CONTEXT correction recorded in 05-BASELINE.md): auth_relay_cursor: no tenant column, one row per named relay, deployment-wide (migration 27 declares only `name`, `lastEventId`, `updatedAt`); not mirrored by a replica because a relay reads its cursor from the primary only (`RelayCursorStoreSql.get`) and must never resume from a stale position. rate_limit_buckets: no tenant column, a bucket is keyed by `bucket_key` alone; not mirrored because it is a read-modify-write counter (one atomic upsert, plus `peek`) always on the primary and never a display/history listing (ADR-EA-024 decision 2), and because it is opt-in, created by `RateLimiterStoreSql.migrate` under its own ledger rather than by `CoreMigrations`, so a replica of a database without it must not copy it.
