### Answers to the audit questions

1. **Cross-organization hijack.** The owner-row primary key arbitrates (`DomainClaims.ts:177`), every domain's owner is checked before any claim row is written (`:179-189`), the lock never crosses organizations, and a concurrent owner release fails closed. The by-id SAML paths take the organization from the stored row; the OIDC store scopes `findById` by the caller's organization before it claims (`OrganizationConnections.ts:498`).
2. **Suspended versus missing.** One read, one branch, one value, one sentence (T-04-08, T-04-13, T-04-17); remove is the only ungated write and is a stated policy.
3. **Advisory-lock key.** Bound parameter, per organization, transaction-scoped, test-pinned (T-04-21).
4. **Lock across external IO.** None after WR-02: sealing moved to `prepare` (T-04-18); SAML does no IO inside its writes.
5. **Orphan claims.** Failed write, deletion, deletion racing create, update racing deletion and removal racing update each end with no claim (T-04-09, T-04-11, T-04-19, T-04-22).
6. **`isGone`.** It releases only the unit's own organization and connection claims and runs before a whole-transaction rollback on SQL (T-04-19).
7. **SCIM.** Unchanged, one test file added (T-04-24); the orphan is recorded and accepted (T-04-25).
8. **Secrets.** Same codec and AAD, envelope bound to the connection id and `Redacted`, no new logging of values (T-04-23).
