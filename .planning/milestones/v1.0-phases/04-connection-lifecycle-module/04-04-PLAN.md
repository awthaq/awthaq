<objective>
Build the one exposed organization service that owns the SAML/OIDC connection lifecycle: the suspended-organization gate, claim-then-write atomicity with compensation, claims-first removal, the single domain normaliser and the release on organization deletion, parameterised by a protocol descriptor. No protocol uses it yet (04-05 and 04-06 migrate them).

Purpose: CONN-01..04. CONTEXT Decided "the suspended check is a policy of the service: one `findActive` gate on create and update inside the lifecycle module, so SAML and OIDC cannot diverge". The template-method shape (RESEARCH "Service shape" candidate 1) lets the protocols keep validation, ids, events and cache invalidation while the invariant sequence exists once.

Output: OrganizationConnectionLifecycle.ts, its exposure in OrganizationSystem, its root export, its unit test, and any declaration-emit union that tsc names.
</objective>

<assumption_delta_decision>
noun: connection (of a protocol), owned by the organization: `OrganizationConnectionLifecycle` over `ConnectionProtocol { protocol, refuse, taken }`
decision: promote
rationale: SAML and OIDC are two protocols of one lifecycle; the general sequence becomes the primary owner in `organization` and each protocol is demoted to a descriptor plus its `prepare`/`write`. Adding alongside (a SAML sequence with an OIDC copy) is exactly what drifted today (SAML create accepts a suspended organization, SAML update has no gate).
invariant test: 04-07 extends `RecordsBoundary.test.ts` so no package `src` outside organization imports `DomainClaims` (a protocol cannot claim a domain except through the lifecycle); it goes red the moment a future protocol reintroduces its own claim sequence.
</assumption_delta_decision>

Target API of packages/organization/src/OrganizationConnectionLifecycle.ts (names are decisions; generic parameter names may follow house style):
- `interface ConnectionProtocol<Refused, Taken>`: `protocol: string` (the value claim rows store: "oauth", "saml"), `refuse: (reason: string) => Refused`, `taken: (domain: string) => Taken`.
- `interface Prepared<A, E, R>`: `connectionId: string`, `domains: ReadonlyArray<string>` (already normalised), `write: Effect.Effect<A, E, R>`.
- `interface PreparedUpdate<A, E, R>`: `connectionId: string`, `domains: ReadonlyArray<string> | undefined` (undefined: the update names no domains, so no claim and no transaction, exactly as today), `previous: ReadonlyArray<string>`, `write: Effect.Effect<A, E, R>`.
- `normalizeDomains(protocol, domains): Effect.Effect<ReadonlyArray<string>, Refused>`: moved from OrganizationConnections.ts:338-348 (the `DOMAIN` regex, trim, lower-case, de-duplicate in first-seen order; an invalid one fails `protocol.refuse(\`"${bad}" is not a valid email domain\`)`, the exact text both stores use today). A plain exported function, not a service method: it is pure and callers run it inside their `prepare` at today's position, so error precedence is unchanged.
- `interface OrganizationConnectionLifecycleShape`: `create(protocol, organizationId, prepare: Effect<Prepared<A, E, R>, EP, RP>)` returning `Effect<A, Refused | Taken | E | EP | StoreUnavailable, R | RP>`; `update(protocol, organizationId, prepare: Effect<PreparedUpdate<A, E, R>, EP, RP>)` with the same result shape; `remove(protocol, organizationId, connectionId, previous, write: Effect<A, E, R>)` returning `Effect<A, E | StoreUnavailable, R>`. Use the StoreUnavailable class the directory and DomainClaims already return (`StoreFailure.StoreUnavailable` from `@awthaq/sql`).
- `class OrganizationConnectionLifecycle extends Context.Service<OrganizationConnectionLifecycle, OrganizationConnectionLifecycleShape>()("awthaq/plugin/organization/ConnectionLifecycle")` with `static readonly layer = Layer.effect(...)` requiring `DomainClaims.DomainClaims`, `OrganizationDirectory.OrganizationDirectory`, `SqlTransaction.SqlTransaction` (the `OrganizationDirectory` class at OrganizationDirectory.ts:151-155 is the model).
- `claimsOnOrganizationDelete = OrganizationDeletion.contribute({ id: "organization.domainClaims", order: -1, make })` whose handler's `inTransaction` is `claims.releaseAllForOrganization`.

Sequences (GONE = "the organization does not exist"):
- create: findActive (None: fail refuse(GONE)) -> `prepare` -> `transaction.withTransaction(` claim `{ organizationId, protocol: protocol.protocol, connectionId, domains }` -> findActive again (None: fail refuse(GONE)) -> `write` `)`; inside the transaction effect `Effect.onError` runs `claims.release(organizationId, connectionId)` with `Effect.ignore`; outside, `Effect.mapError` turns `DomainClaims.DomainClaimTaken` into `protocol.taken(error.domain)` (the verbatim `instanceof` mapping of `DomainClaims.withClaim`) and `Effect.catchTag("SqlError", StoreFailure.storeUnavailable("OrganizationConnectionLifecycle.create"))`.
- update: findActive gate -> `prepare`; `domains === undefined`: run `write` alone; otherwise the create unit without the re-check, compensation `claims.claim({ ..., domains: previous })` inside the unit, label "OrganizationConnectionLifecycle.update".
- remove: no gate; `transaction.withTransaction(` `claims.release(organizationId, connectionId)` -> `write` `)` with `Effect.onError` re-claiming `previous` inside the unit; label "OrganizationConnectionLifecycle.remove".
- The template is `DomainClaims.withClaim`/`withRelease` (DomainClaims.ts:203-239) with three deliberate changes: the compensation moves inside the transaction effect, remove is claims-first, create re-checks under the lock. Those two helpers stay in DomainClaims.ts until 04-07.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| protocol store (SAML, OIDC) -> lifecycle | the caller supplies `prepare` and `write`; the module decides whether the organization may hold a connection and its domains |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-09 | Denial of service | orphan claim or owner rows holding a domain (failed write, organization deletion, deletion racing create) | high | mitigate | Compensation inside the unit (memory gives back, SQL rolls back); release-all at order -1 inside the deletion transaction; re-check under the organization lock on create; unit cases plus race case 3 (green in 04-05). |
