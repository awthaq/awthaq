## Flake root causes

- **Schema leak (real):** `TestSql.layer` never dropped its per-case Postgres schema, so one full run left 843 schemas (652 MB) and a second run on the same container 1591 (1204 MB). It now drops on scope close (4 schemas, about 131 MB after any number of runs); `TestSqlRelease.test.ts` fails when the release is mutated out.
- **Admin `ImpersonationRecords create [atomic]`:** the interrupted-create loop interrupted after N yields, and a yield does not wait for I/O, so Postgres ran 200 to 278 iterations (memory 17). It now uses a widening stride (about 40 iterations).
- **Passkey ChallengeStore tampered consume:** a test defect, no timing. The last base64url character of a 32-byte challenge carries 2 bits, so about 6.4% of challenges decoded to the same bytes. Now tampers the first character (3 of 30 runs failed before, 0 of 30 after).
- **RateLimiterStore sweeper:** `TestClock.adjust` only wakes the sweeper; its DELETE is a real round trip. The case now reads until the delete lands (not reproduced before the fix, so a mechanism fix without a before/after count).
- **`TestSql` clients** commit with `synchronous_commit=off` (hundreds of DDL commits per layer build).
- **Timeout budget (a judgement call):** `e97770f4` gives the 22 SQL-backed project configs a 60 s case budget under `AWTHAQ_POSTGRES_URL` (the BDD suite and `scripts/test-pg.sh` already had it), because 150 ms cases measured 4.5 to 5.1 s in full parallel runs on a heavily loaded machine (load average 20 to 95). Revert this one commit if any budget raise is unwanted.

## Still open

- **`TenantMiddleware` pair** (suspended-organization and unfiltered-query cases): not reproduced (0 of 10 under load after the fixes) and no mechanism isolated; attributed to load worsened by the schema bloat, not proven.
- Load victims seen in full runs before the budget commit (`ScimAtomicity` A1/A8, `ConnectionLifecyclePins` "a failed create holds no claim", admin `endEpisode [race]`) are only as robust as the host allows; the final two full runs were green at load average about 50.
- Two vitest processes running the same suite against one database collide on worker-keyed schema names (pre-existing); a killed run still leaves its schema.
- `kid` for remote signing keys may be a non-canonical string whose Postgres collation order can differ from memory's code-unit order on equal `createdAt` (canonical uuidv7: 0 of 20000 differ). Not fixed: `COLLATE "C"` is locked out and SQLite rejects it.
- CI confirmation of every Postgres result is still open (no git remote).
