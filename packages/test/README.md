# @awthaq/test

Test harness (dev-only: no `src` imports it, no package lists it under `dependencies`; `pnpm check:contract-tests` enforces it). `TestAuth.layer(Auth.make([...]), options)` runs a composed plugin tuple over memory, or over a migrated SQL database with `records: "sql", suite`, so a wire-level test needs no hand-built middleware and no database setup (BEH-EA-193–200).

- `TestAuth.layer` is `AuthHost.layer` (from `@awthaq/server`) over the test ports and the redaction guard (BEH-EA-342): the host module derives the middleware the composed groups declare, selects every plugin's `records` bundle and `hookPoints`, provides the core services over `Persistence.memory` / `Persistence.sql()` (migrated with `Migrations.apply`) and the registries; the harness adds a cheap hasher, `Mailer.layerMemory`, a permissive limiter, a fixed key, the platform crypto and the HTTP platform. Its `RIn` is `never` exactly when the composition is complete, and a tap on a point no composed plugin declares does not compile.
- `options`: `services` (the test's own config, adapters and doubles, merged into the output), `decorate`, `taps`, `csrf`, `principalResolver`, `rateLimiter`, `tier` (`"all" | "public" | "admin"`), `openapiPath`/`docsPath`.
- `TestAuth.app(layer)` serves it (`handler`, `run`, user agents from `agent()` and `signIn(email)` that keep cookies, echo CSRF and follow rotations, `request` from a fresh agent, `dispose`, plus `runtime`, `memoMap`, `context()` and, with `{ testClock: true }`, `advance`); `buildContext` builds any layer into a context on the real clock; `csrfToken`, `csrfSetCookie`, `httpClient`, `encryption`, `recordModes`, `throwingFramework` and `TestSql` complete the kit; `runPluginContractTests` is the plugin contract suite (every plugin class runs it from `test/Contract.test.ts`).
- `RecordsContract` is the record-store contract (plan 25, ADR-EA-041 decision 9): one `RecordsContract.suite(Store, { operations })` per store, every operation classified `read` / `write` / `atomic` (with a `race` case) / `exempt`, keyed by the store's `/records/` key. `runPluginContractTests` requires `records: { suite, suites }` for a plugin whose bundle provides a store, reads the adapters from `Plugin.records` and runs every case on memory and SQL (Postgres under `pnpm test:pg`), a fresh adapter per case.

See [`docs/plugin-authoring.md`](../../docs/plugin-authoring.md#testing-a-plugin) and [`spec/behaviors/25-testing-harness.md`](../../spec/behaviors/25-testing-harness.md).
